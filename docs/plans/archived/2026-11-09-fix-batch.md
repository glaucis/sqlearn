# Fix batch, 2026-11-09: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the open issues an agent can finish (#32, #35, #37, #38, #39,
#40, #31, #28) and do the measuring part of #27, before the next 3.3 area.

**Architecture:** Each task is one issue, fixed where the issue points, test
first. No new public API. The one new private module is
`src/sqlearn/metrics/_labels.py`: the label checks that accuracy (Task 2) and
the per-class metrics (Task 3) share.

**Tech Stack:** Python 3.12+, DuckDB 2.x, pytest, uv, just.

**Spec:** each issue's body is the spec of its task (`gh issue view N`), read
with the area spec it names: `docs/specs/library-metrics.md` (Tasks 2, 3),
`docs/specs/library-model-selection.md` (Tasks 4, 5, 6),
`docs/specs/library-preprocessing.md` (Tasks 1, 7, 8).

## Global Constraints

- Computation is SQL run by DuckDB; Python is the glue (ADR 0002). No row
  loops in Python over the data.
- The only runtime dependency is `duckdb` (ADR 0004). Test-only libraries
  already in the dev group may be used in tests.
- Every refusal is a `SqlearnError` (or its subclass) in the house form:
  what happened, why, then `Fix:`. No raw DuckDB, Optuna or Python exception
  reaches the user for a case a task covers.
- Results agree with scikit-learn where scikit-learn defines them (ADR 0003);
  floating-point results are compared within a bound, never byte for byte
  (ADR 0043).
- Test names use `GLOSSARY.md` terms and read as sentences
  (`test_<behaviour>`); tests go through public seams (`sq.*`, `Pipeline`,
  `Search`, a metric's `compute`) unless the issue names a private function.
- British English in prose, American spelling in identifiers (ADR 0010).
- Every new module gets its test module (`just check-mirror`).
- Commits name their issue: `fix: ... (#N)`. No AI attribution anywhere.
- Before each commit: `just fmt`, `just check`, `just test`. Before the
  branch is called done: `just verify`.

## Review Focus

1. A label column of a type nobody planned for (DATE, TIMESTAMP, BOOLEAN,
   UUID, DECIMAL, ENUM): metrics refuse it plainly or score it right, never
   a raw DuckDB error. Task 3 tests DATE against INTEGER and BOOLEAN against
   BOOLEAN (scored).
2. An ENUM feature whose values a later batch or fold does not hold: codes
   must still match training. Task 4 tests a fold missing one ENUM value.
3. A model whose prediction type widens only in a late batch: no value
   changes. Task 6 tests integers then fractions.
4. Two-pass variance on a constant column and on one row: the standard
   deviation is exactly 0, as before, and Scale's zero-spread rule still
   holds. Task 8 tests both.
5. A search that fails on its first setting: the Optuna study holds no
   RUNNING trial and the original error is the one raised. Task 5 tests it.

### Task 8: Two-pass variance for Scale (#28)

**Files:**

- Modify: `src/sqlearn/agg/aggregates.py:506-515` (`std`), staged the way
  `median` (line 358) is staged (ADR 0032)
- Modify: Scale's bound in its validation
  (`validation/sqlearn/preprocessing/`, the scale validator and
  `scale.results.json`), and the aggregates' validation
- Create: a short section in `docs/benchmarks/` with the cost on large data
- Test: `tests/src/sqlearn/agg/` (the aggregates' test module),
  `tests/src/sqlearn/preprocessing/test_scale.py`

Decision: `std` becomes the population standard deviation by two passes:
the mean with `favg` in one stage, then `sqrt(favg((x - mean)^2))` in a stage
that reads it. Keep `ddof=0`. Missing values are filtered as every aggregate
filters them.

- [ ] **Step 2: Run it; expected FAIL** at about 12 ULPs.
- [ ] **Step 3: Stage `std` in two passes.** Tests for a constant column and
  a single row: exactly 0.
- [ ] **Step 4: Measure cost** against `stddev_pop` on 20M rows under a
