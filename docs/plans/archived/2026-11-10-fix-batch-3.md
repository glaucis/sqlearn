# Fix batch 3, 2026-11-10: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close #53, #52, #47, #48, #51, #50, #27 and #31.

**Architecture:** One task per issue, test first, on branch `fix-batch-3` in
a worktree. The tasks touch separate files except Tasks 3 and 4 (both
`src/sqlearn/datasets/generated.py`; run in order). Every new behaviour
follows [ADR 0046](../../adr/0046-sqlearn-warns-the-user-chooses.md): today's
behaviour stays the default, a better choice is an opt-in setting, and a
`SqlearnWarning` in the house form names it only when the user left the
default.

**Tech Stack:** Python 3.12+, DuckDB 2.x, pytest, uv, just.

**Spec:** each issue's body and its 2026-11-10 decision comment
(`gh issue view N --comments`) is the spec of its task, read with ADR 0046.

## Global Constraints

- Computation is SQL run by DuckDB; Python is the glue (ADR 0002).
- The only runtime dependency is `duckdb` (ADR 0004); `lightgbm` is a dev
  dependency only.
- Refusals are `SqlearnError` in the house form: what happened, `Why:`,
  `Fix:`. Warnings are `SqlearnWarning` in the same form, raised with
  `skip_file_prefixes` as `src/sqlearn/preprocessing/bin.py:389` does, so
  they point at the user's line.
- An explicit choice is never warned about (ADR 0046).
- Floating-point results are compared within a bound (ADR 0043). `just
  verify` rewrites `validation/**/*.results.json`: keep those diffs only
  where a task changes the validation. Commit `tests.json` when tests are
  added.
- Test names read as sentences in `GLOSSARY.md` terms, through public seams
  (`sq.*`, `Pipeline`).
- British English in prose, American spelling in identifiers (ADR 0010).
- Commits name their issue (`feat: ... (#N)`, `docs: ... (#N)`). No AI
  attribution.
- Before each commit: `just fmt`, `just check`, `just test`. Before the
  branch is done: `just verify`, and the docs rebuilt clean
  (`rm -rf docs/reference/generated docs/_build && just build-docs`).

## Review Focus

1. A warning raised inside a search repeats once per fold: the encoders'
   lookup warning (Task 8) must show once for one configuration. Task 8
   tests a 5-fold search warns once.
2. `ordered=True` with `preserve_insertion_order` off still gives the same
   rows as the default with it on, `limit` included. Task 4 tests both.
3. A database table edited and checkpointed between two `train` calls of
   one pipeline in one process (not only across processes): Task 6 tests
   the in-process key changes too.
4. `sq.agg.median(approx=True)` inside a larger learned expression
   (`x - median(x, approx=True)`) and on a column of NULLs only. Task 7
   tests both.
5. `lookup="hash"` on categories holding quotes, NULL learned as a
   category, and an unseen value: the codes equal `lookup="list"`'s. Task 8
   tests all three.

- [ ] **Step 1: Measure.** Run the benchmark's encoders part with

    `lookup="hash"`: no warning.
  - `test_the_lookup_warning_shows_once_in_a_search`: a 5-fold search over

  - `test_hash_is_refused_on_a_column_that_is_not_text`.

- [ ] **Step 4:** Tests pass; both docstrings say when to choose which,

  `feat: encoders take lookup="hash" (#31)`.
